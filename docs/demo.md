# Key · 面试演示脚本

> 用途：把「Key」在一次面试里讲清楚——**一条主线**走完，有 Key 走现场、无 Key 走样例。
> 建议时长：5–8 分钟。全程只讲一条主线：**让 AI 的自信变得可追责**。

---

## 0. 演示前 3 分钟自检

| 检查 | 命令 / 动作 | 通过标准 |
|---|---|---|
| 服务在跑 | `npm run dev` | 打开 http://localhost:3000 正常 |
| 端点可达 | `npm run demo` | 全部 `[OK]`（校验 / · /sample · /compare · /compare/sample · /api/health） |
| 模型可用 | 首页无「尚未配置 LLM」提示，或点一次连通性测试 | 返回「正常」 |
| 兜底就绪 | 记下 `/sample` 与 `/compare/sample` 两个地址 | 断网 / 无额度也能演示 |

> 若网络或额度有风险，**直接走「演示 B」**，别在现场赌模型响应。

## 演示 A · 完整现场（有 Key）

### 1. 首页 — 立主线（20s）

**操作**：停在首页。

**讲**：「这是一个 AI 产品拆解助手，主线只有一句话：**让 AI 的自信变得可追责**。四个环节——**看见 → 可追溯 → 一致 → 经得起质询**——我按这条线走一遍。」

### 2. 开始拆解（10s）

**操作**：输入「Notion」→ 开始拆解。

**讲**：「输入可以是文本 / URL / 截图 / PDF，这里用文本最快。」

### 3. 分析直播页 — 讲「看见」（60s）

**操作**：停在直播页，等卡片依次点亮。

**讲**：「10 个角色的编队：5 个分析师**并行**跑，随后访谈官、反方质疑官、答辩官、综合官、PRD 撰写官**串行**推进。全部经 SSE 逐字流式——过程可见，不是一个转圈。**任何单点失败都不会让整场分析崩掉**，失败的卡片标红，其余继续。」

### 4. 报告页 · 顶部总览 — 讲「可追溯」（60s）

**操作**：点「查看完整报告」→ 指向顶部「**N% 可追溯输入**」计数条。

**讲**：「每条关键结论都带证据标签：**已核实 / 推测 / 缺失**。而且有个硬约束——**「已核实」必须能机械核验回本次输入**，找不到来源就自动降级为『推测』。这是我治 AI 幻觉的方式：不是让它别胡说，而是让它的自信**可被核验**。」

**操作**：展开一条结论（点开 `结论 → 来源`）。

### 5. 第 2、3 段 — 讲「一致」（40s）

**操作**：对比「用户与场景」与「用户访谈实录」两段。

**讲**：「这是**画像先行**：用户研究员先立 persona，访谈官用**同一套画像**展开访谈——两段的 persona 是同源的，不会各说各话。依赖在图里是**显式声明**的，不是靠约定。」

### 6. 反方质疑 / 质疑答辩 / 综合结论 — 讲「经得起质询」（60s）

**操作**：连看「反方质疑」「质疑答辩（逐条回应）」「综合结论与建议」三段。

**讲**：「这就是**真辩论**：质疑官先挑战假设，**答辩官逐条回应**——接受 / 反驳 / 存疑，然后综合官做**裁决**，分歧在报告里显式呈现，而不是被抹平。单轮收敛、依赖图无环，所以**不会无限辩论**。」

### 7. 视觉设计 + 界面代码段 — 展示「不止于文字」（40s）

**操作**：滚到「视觉设计拆解」与「界面代码」段；在代码面板点复制；下方预览画布点选元素、改 class。

**讲**：「视觉设计拆解给出色板 / 字体层级 / 间距 / 组件 / 布局；界面代码段把它变成可复制的 HTML + Tailwind **参考起点**——注意措辞是『参考起点，请自行设计』，不是复刻。」

### 8. 导出与历史（20s）

**操作**：点「下载报告（Markdown）」与「导出 PRD Issues」；打开 `/history`。

**讲**：「报告可导出，PRD 用户故事一键转 GitHub Issues；每次分析落本地历史。」

## 演示 B · 无 Key / 断网降级（备用主线）

1. 打开 **`/sample`** — 「这是内置样例报告，断网也能完整演示：可信度总览、证据标签、10 段结构都在。」
2. 打开 **`/compare/sample`** — 「多产品对比：三个产品各自拆解后，由『对比官』产出**并列对比表**。」

**讲**：「演示环境不可控，所以我准备了**样例回放**——关键能力不依赖现场网络。」

## 演示 C · 对比矩阵与质量门禁（加分项）

### 对比矩阵

**操作**：`/compare` → 填 2-3 个产品 → 开始对比。

**讲**：「每个产品独立跑一遍完整编队，再由对比官横向对比。成本是 **产品数 × 编队规模**，所以编排层**并发受限**、产品数上限 3，这是有意的成本护栏。」

### 质量门禁

**操作**：终端 `npm run eval`。

**讲**：「这是我给自己加的质量门禁：固定的 golden briefs → 跑完整编队 → **judge** 按 4 个维度打分 → 与基线对比，输出『改动前 / 后』的质量变化表。注意——judge 是**代理指标、有噪音**，我只用它做**相对比较**，不当真理。」

## 收尾 · 三个技术决策点（选讲）

- **自研依赖图，不用 LangGraph**：编排逻辑就是「依赖图 + 事件流」，自研可控、每行都能讲清；拓扑调度 + 环检测保证终止。
- **证据归一化用「降级」不用「硬卡」**：解析不通过就降级为纯文本，绝不因为一条坏证据炸掉整条链。
- **零新增依赖的质量门禁**：eval CLI 用 Node 原生 TS 能力 + 一个把 `@/` 别名映射到仓库根的 loader 运行，不为一个脚本引入构建器。

## 常见翻车与兜底

| 风险 | 兜底 |
|---|---|
| 模型响应慢 / 超时 | 切演示 B（样例）；或先讲架构再看历史记录 |
| 无额度 / 网络断 | 演示 B；`npm run eval` 只讲不跑 |
| 模型不支持多模态 | 别用截图输入，改用文本 / URL / PDF |
| dev server 端口被占 | Next 会自动换端口，以终端打印的 `Local:` 为准；或 `npm run demo` 里设 `BASE_URL` |
